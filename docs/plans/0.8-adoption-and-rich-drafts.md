# v0.8 Adoption and Rich Drafts

Status: released in v0.8.0 on 2026-08-16 after maintainer acceptance and the normal release checks.

## Position

Ghost Publisher should remain the narrow, safety-first AI-to-Ghost workflow. Its advantage is not Admin API breadth: it is exact preview/apply, optimistic locking, revision requests, permission profiles, batch preflight, readback receipts, safe scheduling, deployment, and public verification.

The 2026-08-16 competitor snapshot shows three different alternatives:

- [MFYDev/ghost-mcp](https://github.com/MFYDev/ghost-mcp) emphasizes broad CRUD across posts, members, newsletters, offers, users, tags, and webhooks. Its npm package led this sample with 1,462 downloads during 2026-08-09 through 2026-08-15.
- [jgardner04/Ghost-MCP-Server](https://github.com/jgardner04/Ghost-MCP-Server) exposes 34 tools, remote transports, and broad Ghost administration.
- [damusix/ghost-mcp](https://github.com/damusix/ghost-mcp) provides structured native Koenig composition plus a general Ghost API dispatcher.
- [workspace/ghost-mcp](https://github.com/workspace/ghost-mcp) and [weareikko/ghost-tools](https://github.com/weareikko/ghost-tools) offer remote HTTP/OAuth options and broad read/write access.
- Ghost itself supports automation through [Zapier](https://ghost.org/integrations/zapier/), Make, webhooks, and the Admin API.

Ghost Publisher recorded 132 npm downloads during the same 2026-08-09 through 2026-08-15 window. Download counts are a discovery signal, not verified active users.

## Completed locally

1. Release messaging identifies `0.8.0` as the current published package.
2. ChatGPT desktop `26.810.41047` and bundled Codex CLI `0.148.0-alpha.9` passed discovery, redacted setup dry-run, and a read-only connection check against Ghost `6.42`. Cursor and Claude configuration targets were detected, but current application runtimes were unavailable.
3. The [safe publishing demo](../safe-publish-demo.md) covers setup, native draft creation, exact readback, signed preview, separate approval, apply receipt, publish approval, and live verification.
4. No telemetry was added. Public npm downloads, compatibility reports, issues, and pilot feedback remain the only adoption signals.

The proposed non-maintainer demo gate was replaced by explicit maintainer acceptance based on regular use of the integration. The reproducible workflow remains available for compatibility reports.

## Implemented pilot: native rich-card drafts

`create_drafts` and `create_page_drafts` now accept exactly one of Markdown or a structured-block array. The initial block set is `heading`, `paragraph`, `callout`, and `button`; no general-purpose API tool was added.

The tools still create drafts only. Button URLs require HTTP(S), callout Markdown is rendered with raw HTML disabled, and existing post/Page edits remain behind the signed change-set boundary. Unit/schema tests and disposable `ghost:5-alpine` plus `ghost:6-alpine` integrations proved node readback and preservation through the existing section-insertion flow.

The technical success condition and release checks are complete.

## Later, only with demand

- Remote HTTP/OAuth: require a concrete hosted-user workflow, credential threat model, tenant isolation, revocation, abuse limits, and operational owner.
- Members, newsletters, offers, tiers, tags, webhooks, themes, and deletes: require a separate permission-scoped product decision; they do not belong in the safe publisher by default.
- Local Markdown synchronization: use the host client's filesystem first. Add MCP state only if repeated workflows prove host orchestration insufficient.
- Automatic rollback: retain Ghost revisions and reversible signed changes; do not promise restore until Ghost exposes a documented stable integration endpoint and partial-failure semantics are tested.

## Explicitly skipped

Do not chase competitor tool counts, arbitrary Admin API dispatch, embedded AI providers, dashboards, analytics storage, background jobs, or telemetry. Those features weaken the current safety and local-first differentiation without proven demand.
