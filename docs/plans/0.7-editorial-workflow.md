# v0.7 Editorial Workflow

Status: released in v0.7.0 on 2026-08-02 after package checks, skill validation, disposable Ghost 5/6 integration, npm publication, and MCP Registry verification passed.

The current `v0.10.1` release retains these workflows and adds deterministic Publication Doctor findings without changing the signed write boundary.

v0.7 extends the signed change-set union with three draft-only structure-safe operations:

- `append_section` and `prepend_section` sanitize Markdown with raw HTML disabled, add one Ghost HTML-card Lexical node, and verify every original root child remains deep-equal after Ghost readback.
- `replace_exact_text` accepts one exact, unique text node and preserves its other properties. Zero, multiple, cross-node, and card matches are rejected.

`audit_content` reports mechanical evidence only: Lexical parseability and inventory, missing feature-image alt text and metadata, title/metadata lengths, Lexical links, and Sources/Kaynaklar heading detection. It does not crawl, score, or judge truth or reliability.

`plan_schedule` uses `@js-temporal/polyfill` for IANA time-zone conversion on Node 22. Ambiguous, missing, or invalid local times are rejected. Intervals are exact elapsed hours. The returned order and UTC timestamps are bound to the site and current revisions with an HMAC. `schedule_posts` requires that plan and a separate confirmation, never sends newsletter parameters, and reports headless visibility as configured or unverified.

The package includes a minimal `ghost-editorial-batch` skill covering connection, exact reads, audit, preview, separate content approval, apply/readback receipts, separate schedule planning and approval, and recovery evidence. Research and writing remain host-AI responsibilities.

Release validation included unit/contract checks, skill validation, audit and package gates, plus disposable Ghost 5 and Ghost 6 round trips proving original Lexical children survive section insertion.
